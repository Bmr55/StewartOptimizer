# Stewart Optimizer quick start

1. With Node.js >=22, run `npm run dev` from the repository root and open the printed local URL. Use `npm run dev -- --port 8001` if needed. No package installation is needed. Other static HTTP servers also work.
2. Keep the automatically loaded [sample requirements](../examples/sample-requirements.json), or edit it using the [input reference](./REQUIREMENTS.md). Flat JSON is also supported. Ranges are offsets from home in mm; input rotations are degrees.
3. Begin with population 12, generations 5, mutation rate 0.35, Compact objectives, and the default 1,024 Halton workspace samples. Full adds five search objectives; both sets retain all diagnostic metrics. The bundled sample budgets 92,232 pose checks with the default adaptive cycle sampling (1,024 workspace poses, up to 256 cycle samples and one home check for each of 72 candidates); the legacy fixed 64-phase schedule budgets 78,408. Choose 256 for a quicker pass, 4,096 for a deeper sample, or Cartesian grid to use the axis steps. Grid cost grows as the product of all six axis counts. Requests over 100,000 workspace poses/layout or 1,000,000 budgeted checks/run are rejected before evaluation.
4. Adjust controls as needed. Mutation rate accepts 0 through 1, including zero. The visible seed starts at 1 and is reused on every run until edited or changed with Randomize. Explicit range edits survive Run; untouched controls follow edits to the JSON. Loading the sample resets range controls. Strict joint evaluation is the default; optional soft exploration reports a separate relaxed score. Optional shared and per-servo ratings are enforced unless advisory mode is selected.
5. Select Run Optimization and observe elapsed time, completed candidates, generation, front size, best completed candidate, actual versus budgeted pose work, and approximate remaining time. ETA appears after three candidates complete. The browser runs the search in a module worker so controls remain responsive. Cancel stops an active sweep. If a complete population exists, its results remain available and are marked partial. If worker startup fails, the page offers an explicit **Run on main thread** fallback.
6. Inspect feasible coverage, cycle validity, joint violations and modeling limitations. Select a candidate in the result browser; **Copy JSON** copies the on-screen result. Download Layout JSON saves its geometry, metrics, feasibility, policy and run status; construction coordinates and Fusion script exports are also available for candidates with valid home geometry. To refine a previous design, paste its JSON into the separate [reference layout input](./IMPORT.md).
7. Open **Simulate** to view the selected candidate with the native WebGL2 renderer. The Optimize and Simulate candidate selectors stay in sync, and tab switches retain the pose and camera. Adjust X/Y/Z and Rx/Ry/Rz, play an animation, or use keyboard/gamepad input. Mouse drag orbits the camera; **Move platform** explicitly changes drag behavior. Invalid requests stay visible in the status and diagnostics while the rendered pose remains at the last accepted request. Mechanical controls create an editable copy without changing the selected optimizer result. Send current geometry back through **Use geometry as optimizer reference**, or save the layout and simulator state as JSON. See [active simulator](./SIMULATOR.md).

The example does not guarantee a feasible design. Both Halton and grid coverage describe evaluated poses only, so failures between samples can be missed. Supplied servo ratings are compared with modeled cycle demand; collisions are not checked. [Results and export details](./RESULTS.md) and the [cycle model](./CYCLE_MODEL.md) explain what the reported values establish.

Run `npm test` for automated regression checks and `npm run smoke` to verify a complete default sample and export. After `npm ci`, run `npm run test:browser`, `npm run test:browser:geometry`, and `npm run test:browser:diagnostics` for browser checks; they launch Google Chrome through Playwright, or Playwright's bundled Chromium when Chrome is not installed (`PLAYWRIGHT_CHANNEL` picks a channel explicitly). The active simulator requires desktop WebGL2; if it is unavailable, the optimizer still works. The [archived simulator](../archive/simulator/README.md) launches separately and uses different legacy math.
